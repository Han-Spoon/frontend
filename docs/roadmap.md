# 후속 작업

## 서버·AI 합의가 먼저 필요한 것

1. explainability 필드와 포함 확률의 산출·검증·보정 정책.
2. 식당 CSV의 ID, 좌표, 원명, 영문/별칭, 운영 정보, 사진 출처.
3. 지도 SDK, 위치 권한/거부 상태, 주변 검색 반경과 정렬.
4. 방문/스캔/선호 저장 API, 멱등성, 계정별 접근, 삭제와 보관 기간.
5. 실제 후기 질문/집계 단위와 노출 최소 표본, 순위의 안정성.
6. 통화 선택과 매일 자정 갱신 배치, 환율 실패 시 마지막 갱신 시각 표시.

## 프론트 후속

- 식당 개별 프로필별 랭킹 세분화와 정렬 기준 공개.
- 저장한 식당 컬렉션 및 메뉴 선호 페이지 확장.
- 결과 상세 URL과 새로고침 복원.
- 새 큐레이션 4개 언어 장문 번역 및 7개 언어 원어민 검토.
- 이미지 자체 호스팅/출처 관리, 지도 로딩/실패/빈 결과 상태.
- 화면 단위 lazy loading으로 번들 크기 완화.
- 전체 TypeScript 검사, CI, 실제 API 통합 테스트.

## 제휴 실험 제안

식당 페이지 → 다국어 식단 요청 안내 → 현장 QR 메뉴 스캔 → 선택형 경험 피드백이라는 흐름을 우선한다. 파트너에게는 익명화·집계된 의사소통 개선 항목을 제공한다. 식단 성향을 개인 식별 가능한 형태로 식당에 넘기지 않는다.

제휴 노출은 별도 영역과 표시 규칙을 갖는다. 유료 계약이 안전 판정이나 식단 랭킹을 바꾸지 않게 한다. 예약/쿠폰/결제/실제 방문 인증은 사업 조건과 서버 계약 후 구현한다.
