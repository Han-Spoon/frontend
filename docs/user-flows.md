# 사용자 흐름

## 시작과 로그인

1. `/` 랜딩에서 한스푼의 메뉴 번역·식단 확인·직원 소통 가치를 확인한다.
2. “한스푼 시작하기”를 눌러 `/login`으로 이동한다.
3. Google 계정으로만 로그인한다. 이메일·비밀번호 회원가입과 다른 소셜 로그인은 제공하지 않는다.
4. 기존 프로필이 있으면 홈으로, 없으면 온보딩으로 이동한다.

랜딩과 로그인에서 언어를 바꿀 수 있고 선택은 두 화면과 이후 앱에 이어진다. Google ID Token을 받아 기존 `/api/v1/auth/google` 계약으로 전달하는 인증 흐름은 유지한다.

## 식당을 찾는 중

1. 홈에서 5개의 식당 소개/문화 콘텐츠 캐러셀을 본다. 캐러셀은 5초마다 자동 이동하며 모션 감소 설정에서는 자동 이동하지 않는다.
2. 홈에서 청담·부산·강남/역삼 등 18개 지역 칩을 선택하고, 해당 지역 중심 주변의 실제 가게를 지도에서 확인한다.
3. 홈의 지도 핀으로 가게를 바꾸고, 선택 가게 카드나 전체 지도 버튼에서 같은 검색 중심을 유지한 채 풀스크린 `/map`으로 이동한다.
4. 풀스크린 지도 핀을 누르면 식당 상세 바텀시트가 올라온다.
5. 상세에서 입점/전체 레시피 인증 여부, 같은 프로필의 후기, 찜을 확인한다. 입점 식당은 ‘내 프로필로 메뉴 보기’, 그 외에는 ‘이 식당 메뉴 스캔’으로 이어진다.
6. 홈 하단 ‘한 끼가 여행이 되는 곳’에서 선택한 동네의 실제 식당 후보를 사진 카드로 둘러본다. 최대 6곳의 상호·업종·주소를 보여주며 클릭하면 해당 식당이 선택된 지도로 이동한다. 개인화/안전 순위가 아니며 현재 사진은 표시된 메뉴·공간 참고 이미지다. 상세 정책은 `restaurant-recommendations.md`를 따른다.

홈은 지역 칩에 대응하는 중심 좌표를 `POST /api/v1/stores/candidates`에 보내 반경 1km의 실제 가게를 최대 20곳 조회하며 위치 권한을 요구하지 않는다. 홈에서 `/map`으로 이동하면 전달받은 지역 중심 좌표로 즉시 시작하고, 하단 지도 탭에서 직접 `/map`에 진입한 경우에만 브라우저 현재 위치를 먼저 조회한다. 지도를 옮기면 `dragend` 시점의 중심 좌표로 후보를 다시 조회한다. 후보 응답으로 지도 위치를 다시 맞추지 않아 요청이 반복되는 것을 막고, ‘내 위치’ 버튼은 현재 위치가 아직 없으면 그 시점에 위치 권한을 요청한다. 위치 요청이 실패해도 이미 보고 있던 지역 지도는 유지하며, 직접 진입의 위치 거부·오류·8초 시간 초과 시에는 안내한다. 좌표는 후보 조회에만 사용하고 브라우저 저장소나 스캔 기록에는 저장하지 않는다.

## 입점 식당의 촬영 없는 메뉴 확인

홈/지도/촬영 화면의 식당 선택에서 입점 파트너를 고르면 `/restaurants/:id/menu`로 이동한다. 가상 전체 레시피 6종과 현재 프로필을 비교해 기존 결과 카드로 보여준다. 확인된 회피 재료 충돌은 위험, 프로필 없음·종교 인증 확인 필요는 주의로 표시한다. 확률을 임의로 만들지 않는다. 이 동선은 실제 스캔 API를 호출하지 않는다.

하단은 ‘프로필 수정하기 / 기록하기’. 식당이 연결된 상태로 기존 저장 흐름을 재사용한다. 일반 식당은 촬영 흐름을 유지한다. 기록 자체 페이지는 삭제하지 않고 마이페이지에서 계속 접근한다.

## 스캔 전

홈의 스캔 CTA는 식당 선택 시트를 한 번 제시한다. 주변/지역 후보를 누르거나 한글·영문 이름으로 검색한다. “식당 없이 계속하기”로 즉시 넘어갈 수 있다. 하단 촬영 탭에서는 `/scan`으로 직접 들어가고 화면 위 선택 행에서 식당을 연결할 수 있다.

카메라 열기/사진 선택 → 미리보기 → 분석 시작. 실서비스 모드의 카메라 권한 거부, 파일 형식/10MB 제한, 업로드 재시도 처리는 기존 동작을 유지한다.

## 결과

요약과 적용 프로필 → 상태별 개수/필터 → 메뉴명·가격·라이킷 → 주의 재료 확률 → 이유 → 직원 확인·주문 카드 → 펼쳐 보는 근거. 큐레이션은 메뉴 목록 끝에서만 제공한다.

확률은 재료의 포함 가능성이다. 식사의 안전 확률이나 알레르기 반응 확률이 아니다. 직원 답변으로 결과 상태를 자동 덮어쓰지 않는다.

## 저장

하단의 같은 크기 버튼: “다시 스캔하기” / “기록하기”. 기록하기 → 선택적 식당 연결/변경/해제 → 식당을 지정한 경우 선택적 프로필별 의사소통 피드백 → 저장 완료 → 스캔 기록.

- 식당 있음: 방문 기록 이름, restaurantId, 메뉴, 프로필 스냅샷, 선택형 피드백 저장.
- 식당 없음: 일반 스캔 이름, restaurantId=null, 메뉴와 프로필 스냅샷 저장. 식당 피드백은 없음.
- 저장을 반복하면 같은 recordId를 갱신한다. 식당이 바뀌면 입력 중인 후기를 비운다.
- 기록 상세를 다시 열면 당시의 프로필과 메뉴를 사용한다.
- 기록 이름 수정/삭제 가능. 서버 스캔과 로컬 방문 메타데이터는 구분한다.

## 미래 방문 확인

지역 후보 선택은 장소 연결이며 방문 인증은 아니다. 동의 기반 위치 후보와 현장 QR의 조합을 후속 구현한다. QR은 식당 ID를 채우는 것과 서버에서 방문을 검증하는 것을 별개로 설계한다.
