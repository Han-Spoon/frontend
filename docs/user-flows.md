# 사용자 흐름

## 시작과 로그인

1. `/` 랜딩에서 한스푼의 메뉴 번역·식단 확인·직원 소통 가치를 확인한다.
2. “한스푼 시작하기”를 눌러 `/login`으로 이동한다.
3. Google 계정으로만 로그인한다. 이메일·비밀번호 회원가입과 다른 소셜 로그인은 제공하지 않는다.
4. 기존 프로필이 있으면 홈으로, 없으면 온보딩으로 이동한다.

랜딩과 로그인에서 언어를 바꿀 수 있고 선택은 두 화면과 이후 앱에 이어진다. Google ID Token을 받아 기존 `/api/v1/auth/google` 계약으로 전달하는 인증 흐름은 유지한다.

## 식당을 찾는 중

1. 홈에서 5개의 식당 소개/문화 콘텐츠 캐러셀을 본다. 캐러셀은 5초마다 자동 이동하며 모션 감소 설정에서는 자동 이동하지 않는다.
2. 내 주변 또는 청담·부산·강남/역삼 등 18개 지역을 선택한다.
3. 홈의 지도 미리보기나 식당 카드에서 풀스크린 `/restaurants/map`으로 이동한다.
4. 풀스크린 지도 핀을 누르면 식당 상세 바텀시트가 올라온다.
5. 상세에서 입점/전체 레시피 인증 여부, 같은 프로필의 후기, 찜, 이 식당 메뉴 스캔을 확인한다.
6. 식단별·알레르기별·종교별 랭킹에서 다른 식당을 발견한다.

데모의 내 주변은 고정 성수 좌표이며 실제 위치 권한을 요청하지 않는다. 홈 미리보기와 풀스크린 지도는 Naver Maps SDK를 사용한다. 현재 핀은 지역 중심 주변의 가상 식당 좌표이며 운영 DB의 위도·경도가 준비되면 같은 `StoreMap` 입력으로 교체한다.

## 스캔 전

홈의 스캔 CTA는 식당 선택 시트를 한 번 제시한다. 주변/지역 후보를 누르거나 한글·영문 이름으로 검색한다. “식당 없이 계속하기”로 즉시 넘어갈 수 있다. 하단 촬영 탭에서는 `/scan`으로 직접 들어가고 화면 위 선택 행에서 식당을 연결할 수 있다.

카메라 열기/사진 선택 → 미리보기 → 분석 시작. 실서비스 모드의 카메라 권한 거부, 파일 형식/10MB 제한, 업로드 재시도 처리는 기존 동작을 유지한다.

## 결과

요약과 적용 프로필 → 상태별 개수/필터 → 메뉴명·가격·라이킷 → 주의 재료 확률 → 이유 → 직원 확인·주문 카드 → 펼쳐 보는 근거. 큐레이션은 메뉴 목록 끝에서만 제공한다.

확률은 재료의 포함 가능성이다. 식사의 안전 확률이나 알레르기 반응 확률이 아니다. 직원 답변으로 결과 상태를 자동 덮어쓰지 않는다.

## 저장

하단의 같은 크기 버튼: “다시 스캔하기” / “기록하기”. 기록하기 → 선택적 식당 연결/변경/해제 → 식당을 지정한 경우 선택적 프로필별 의사소통 피드백 → 저장 완료 → 스캔 기록.

- 식당 있음: 방문 기록 이름, restaurantId, 메뉴, 프로필 스냅샷, 선택형 피드백 저장.
- 식당 없음: 일반 스캔 이름, restaurantId=null, 메뉴와 프로필 스냅샷 저장. 식당 피드백은 없음.
- 저장을 반복하면 같은 recordId를 갱신한다. 식당이 바뀌면 입력 중인 후기를 비운다.
- 기록 상세를 다시 열면 당시의 프로필과 메뉴를 사용한다.
- 기록 이름 수정/삭제 가능. 서버 스캔과 로컬 방문 메타데이터는 구분한다.

## 미래 방문 확인

지역 후보 선택은 장소 연결이며 방문 인증은 아니다. 동의 기반 위치 후보와 현장 QR의 조합을 후속 구현한다. QR은 식당 ID를 채우는 것과 서버에서 방문을 검증하는 것을 별개로 설계한다.
