# 분식 메뉴판 촬영 시나리오와 결과 UI 계약

2026-09-15. 새 fixture는 `src/app/results/filmingFixtures.ts`에 있으며 기존 경계값 테스트 fixture와 구분한다.

## 시연 진입

- 빠른 확인: 개발 서버 `/dev/results-preview?lang=ko` (en/ar/ja 등도 가능).
- 사진 선택부터 확인: `/scan?lang=ko`. 현재 발표용 릴리스는 `FIXED_SCAN_RESULTS_ENABLED=true`로, 개발/운영 빌드 모두 어떤 지원 이미지(JPEG/PNG/WebP, 최대 10MB)를 넣어도 고정 13개 결과를 반환한다. 이미지 업로드·새 스캔 분석 API는 호출하지 않는다.
- 결과 프로필은 **비건 + 새우**. 계정 프로필은 변경하지 않고 결과·직원 카드·로컬 기록에 별도 스냅샷을 적용한다. 선택한 실제 식당은 결과에 전달한다.
- 홈/지도/인증의 `demoMode`와 별개다. 새 스캔을 실제 API로 복구하려면 위 상수를 false로 변경한다. 기존 서버 기록 조회와 분석 어댑터는 유지한다.
- 사용자 요청에 따라 화면의 시연 안내를 제거했다. 고정 데이터·확률의 출처와 한계는 이 문서에 기록한다. 개발 프리뷰 경로는 운영 빌드에 노출되지 않는다.

## 화면 설계

가격 아래에는 음식 자체의 설명만 표시한다. 서버의 `message`는 식단 안내이므로 `explainability.decisionReason`에 보존하고 음식 설명으로 반복하지 않는다. `riskLevel`, 원래 hits, ownerCard 플래그, 가격은 유지한다.

주의 카드: 짧은 핵심 이유 → 관련 재료별 원형 포함 가능성 그래프 → 직원 확인 행동. 그래프는 기존 `getCautionProbabilities` 필터를 그대로 사용한다. `caution` + 활성 프로필의 회피 재료 + 유한한 0–100 숫자만 표시하며 수치가 없으면 ‘수치 정보 없음’으로 안내한다. 데모의 78%, 46% 등은 **디자인용 임의 고정값**이며 실제 통계가 아니다.

펼친 근거: 재료별 출처·근거 수준 → 숨은 재료의 연결 경로 → 주문 전 확인 체크리스트. ‘근거를 한눈에’ 제목과 네 분석 관점 카드는 제거했다. optional `checks`는 데이터 호환용으로 남기되 화면에 표시하지 않는다.

직원 응답은 모든 선택지에서 같은 메인 초록색이다. 예/아니요/모름의 의미는 문구와 아이콘으로 구분하며 응답을 눌러도 분석 판정이나 그래프를 바꾸지 않는다.

직원 카드의 재료 요청은 활성 프로필과 연결된 재료를 사용한다. 비건 제한으로 표시된 달걀·생선을 알레르기라고 부르지 않는다. ‘빼고 요청’은 중립적인 재료 제거 요청으로 만들고 실제 적용 프로필을 별도로 보여준다.

## AI 팀에 제안하는 확장 출력

현재 `MenuExplainability`의 optional `checks`를 추가했다. 실제 서버 어댑터는 아직 이를 받지 않으며, 아래는 합의용 UI 계약이다. 원본 위험도 필드는 유지한다.

```json
{
  "description": {"ko": "밥과 채소를 김으로 말아 썬 김밥", "en": "Seaweed rice rolls with vegetables"},
  "riskLevel": "caution",
  "explainability": {
    "decisionReason": {"ko": "달걀 지단이 들어갈 수 있어 비건 여부 확인이 필요해요."},
    "checks": [
      {"kind": "menu", "status": "observed", "finding": {"ko": "메뉴판에 야채김밥 · 4,000원 표기"}},
      {"kind": "recipe", "status": "inferred", "finding": {"ko": "일반 김밥에는 달걀 지단을 넣기도 함"}},
      {"kind": "profile", "status": "inferred", "finding": {"ko": "달걀 사용 시 비건 기준과 불일치"}},
      {"kind": "cross-contact", "status": "unverified", "finding": {"ko": "새우와 칼·도마 공유 여부 미확인"}}
    ],
    "ingredients": [{
      "name": {"ko": "달걀 지단", "en": "Egg strips"},
      "profileIds": ["vegan:vegan"],
      "inclusionProbability": 78,
      "confidence": "limited",
      "sourceTypes": ["demo-recipe"]
    }],
    "hiddenIngredientPaths": [[{"ko": "김밥 속재료"}, {"ko": "달걀 지단 가능"}, {"ko": "비건 기준 확인"}]],
    "uncertainties": [{"ko": "달걀 없이 새로 말 수 있나요?"}]
  }
}
```

위 78은 시연 숫자다. 서버 연결 전 확률 산정·보정, 출처 URL/관찰 시각, 근거 수준 기준과 결측 처리를 합의해야 한다. 숫자가 없는 추론을 백분율로 변환하거나 모델의 자신감을 재료 포함 확률로 쓰지 않는다. 각 분석 관점은 배열 원소이며 팀의 에이전트 수가 달라도 계약은 유지된다.

`demo-recipe`는 프론트 시연 전용 출처다. 실제 응답에는 실제 수집한 출처를 사용하며, 매장 레시피가 확인됐다는 의미로 시연 데이터를 보내지 않는다.

## 사진

이미지 생성 없이 Wikimedia Commons의 메뉴별 실사를 사용한다. 원본 파일명·작가·라이선스 URL은 fixture의 `imageCredit`에 있고, 각 메뉴의 펼친 근거 하단에서도 출처로 이동할 수 있다. CSS `object-fit: cover`, 메뉴별 확대/위치를 이용해 음식이 채워지게 크롭한다. 원본 참고 사진은 해당 식당의 실제 음식 사진이 아니다. CC BY/CC BY-SA는 원문 파일 페이지의 해당 라이선스를 따르고 화면 크롭 사실을 표시한다. 사진 실패 시 무관한 사진으로 대체하지 않는다.
